# Charmera-S3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Firmware that turns a Waveshare ESP32-S3-LCD-2 (no touch) + OV5640 into a BOOT-button-and-tilt driven, Charmera-style camera: live viewfinder with 12 looks, 5 MP JPEGs to SD, gallery, and a settings screen.

**Architecture:** ESP-IDF app split into small components: `board` (buses, backlight, battery), `display` (ST7789 + LVGL), `input` (BOOT press + tilt classifiers), `storage` (SD + file naming), `looks` (pure pixel filters/frames), `camera` (OV5640 preview/capture/AF), `pipeline` (strip decode → look → encode → file), `ui` (three LVGL screens), `power` (idle). Pure logic (`looks`, storage naming/maths, `input` classifiers) builds for the host too and is unit-tested there; hardware pieces are verified on the board.

**Tech Stack:** ESP-IDF v5.5.x, LVGL 9 via `espressif/esp_lvgl_port`, `espressif/esp32-camera` (with `CONFIG_CAMERA_AF_SUPPORT`), `espressif/esp_new_jpeg` (block decode + block encode), FatFS over SDSPI, Unity for host tests.

**Spec:** `docs/superpowers/specs/2026-11-06-charmera-s3-design.md` (read it; this plan argues from it). Pin map is in the spec's Hardware table; Waveshare's original demos are at `/tmp/opencode/charmera/demo/ESP-IDF/` (copy anything useful into the repo, don't depend on `/tmp`).

## Global Constraints

- Board: ESP32-S3R8, 16 MB flash, 8 MB octal PSRAM, port `/dev/ttyACM0`.
- ESP-IDF **≥ v5.5.0** (Waveshare requirement). Install to `~/esp/esp-idf`.
- Repo: `~/repos/charmera-s3`. Language C.
- No touchscreen. Controls: tilt left/right = prev/next; BOOT short = shutter/OK, long (≥800 ms) = menu, double (<350 ms apart) = back. Confirm dialogs default to Cancel. Tilt never wakes from idle.
- UI landscape **320×240**, held with USB-C on the right. LCD needs `invert_color=true`, RGB order, 16 bpp, byte-swapped RGB565.
- Full-res photos **2592×1944** (`FRAMESIZE_5MP`). Viewfinder **320×240 RGB565** (`FRAMESIZE_QVGA`).
- Files: `/sdcard/DCIM/100CHARM/IMG_####.JPG`, numbering continues from the highest existing; never overwrite. Write `*.TMP` then rename.
- LCD and SD share SPI2 — every SD access and every LCD flush takes the same bus lock.
- Gallery / delete-all touch only `IMG_*.JPG` in `100CHARM`.
- Frame artwork original — no Kodak logos/trademarks. English only. No video, USB-MSC, Wi-Fi, date stamp in v1.
- Boot straight into the Camera screen.
- Never block boot on autofocus.

## Review Focus

1. **Card pulled or missing while running** → camera shows "No card", shutter disabled, gallery/settings show the state; no crash, recovers when reinserted (re-mount on next action). Test: Task 3 `storage_status` on-device check + Task 7 UI state check.
2. **Card full** → shutter disabled with "Card full" before a capture is attempted. Test: Task 3 host test `test_remaining_zero_when_free_below_estimate`.
3. **Leftover `*.TMP` after power loss mid-save** → deleted at mount, never shown or counted. Test: Task 3 host test `test_tmp_and_foreign_files_ignored` + mount cleanup.
4. **Number 9999 reached** → `storage_next_photo_number` returns -1 and the UI says "Card full (numbering)"; nothing overwritten. Test: Task 3 `test_next_number_exhausted`.
5. **Presses/tilts during "Saving…"/"Focusing…"** → ignored; no second capture queued. Test: Task 7 on-device check.
6. **Holding a tilt or the button** → tilt auto-repeats at a steady rate and a long press fires once, not repeatedly. Test: Task 2b `test_tilt_auto_repeat`, `test_long_press_fires_once`.

```c
#define BTN_DOUBLE_MS 350
```

Roll is computed from the accelerometer; which axis is roll is decided on the board (log raw axes while tilting).

### Task 4: `looks` component — pure filters and frames

**Files:** Create `components/looks/{CMakeLists.txt,include/looks.h,src/looks.c,src/frames.c}`; test `tests/host/test_looks.c`.

**Interfaces — Produces:**
```c
typedef enum {
  LOOK_NORMAL, LOOK_COOL, LOOK_WARM, LOOK_BW,              // sensor-side
  LOOK_PIXEL_RED, LOOK_PIXEL_YELLOW, LOOK_PIXEL_BLUE, LOOK_PIXEL_GRAY, // software
  LOOK_FRAME_STICKER, LOOK_FRAME_PC, LOOK_FRAME_FILM, LOOK_FRAME_CHARMERA, // software
  LOOK_COUNT
} look_t;
const char *look_name(look_t l);          // "Normal","Cool Tone","Warm Tone","Black & White","Pixel Red","Pixel Yellow","Pixel Blue","Pixel Gray","Sticker Frame","PC Frame","Film Frame","Charmera Frame"
bool look_is_software(look_t l);          // true for PIXEL_* and FRAME_*
look_t look_next(look_t l); look_t look_prev(look_t l);   // wrap around
/* Apply to a horizontal strip of an image. `rgb` is RGB888, `strip_w` x `strip_h`,
   whose first row is row `y0` of an image `img_w` x `img_h`. Results must be identical
   to applying to the whole image at once (no seams). */
void look_apply_rgb888(look_t l, uint8_t *rgb, int strip_w, int strip_h, int y0, int img_w, int img_h);
/* Viewfinder: same maths on RGB565 (native byte order). */
void look_apply_rgb565(look_t l, uint16_t *px, int w, int h);
int  look_pixel_block(int img_w);         // img_w/80, min 4 -> 320 wide: 4, 2592 wide: 32
```
Scale-dependent sizes (pixel block, frame thickness) derive from `img_w` so the 320-wide viewfinder and 2592-wide photo look the same. Pixel filter: average each `block×block` cell's luminance, threshold to a 2-tone palette (dark/light shade of the colour). A strip must contain whole pixel blocks — the pipeline guarantees strip heights are multiples of `look_pixel_block(img_w)`; assert it. Frames: procedural drawing (rectangles, stripes, simple shapes, sprocket holes for Film) — no bitmap assets needed; sensor-side looks are no-ops here.

### Task 6: `pipeline` component — save a photo with its look

**Files:** Create `components/pipeline/{CMakeLists.txt,include/pipeline.h,pipeline.c}`; modify `main/idf_component.yml` (add `espressif/esp_new_jpeg`).

**Interfaces — Consumes:** `camera_*`, `storage_begin/commit/abort_photo`, `look_apply_rgb888`, `look_is_software`. **Produces:**
```c
typedef enum { PIPE_OK, PIPE_NO_CARD, PIPE_CARD_FULL, PIPE_CAPTURE_FAILED, PIPE_WRITE_FAILED } pipe_result_t;
typedef void (*pipe_progress_cb)(int percent, void *ctx);   // called from pipeline task
pipe_result_t pipeline_take_photo(look_t look, pipe_progress_cb cb, void *ctx, int *out_number);
```
Flow: check `storage_status()` and `storage_photos_remaining_now() > 0` → `camera_focus(1500)` → `camera_capture_full()` → if `!look_is_software(look)`: write the sensor JPEG straight through `storage_begin_photo`/`commit`; else strip path:
- `jpeg_dec` with `block_enable=true`, output RGB888; accumulate decoded 8/16-line blocks into a strip buffer (PSRAM) whose height is a multiple of both the decoder block and `look_pixel_block(2592)` (=32), e.g. 32 rows.
- `look_apply_rgb888(look, strip, 2592, rows, y0, 2592, 1944)`.
- Feed rows to `jpeg_enc` (`JPEG_PIXEL_FORMAT_RGB888`, quality 95, subsampling **4:2:2** or 4:4:4 because 1944 isn't a multiple of 16) via `jpeg_enc_process_with_block`, sized by `jpeg_enc_get_block_size`; output buffer in PSRAM (allocate 3 MB).
- Write output → commit. On any failure → `storage_abort_photo`, return the error. Free everything on every path.
- Progress callback at each strip.
If the sensor needed EXIF orientation (Task 5 finding), insert an APP1 EXIF Orientation segment after SOI on both paths.
